## 详细原则（完整版）

以下 10 条是**可直接执行的规则**，从上游继承 + 本地实战迭代沉淀。

### P1 技术基础层

#### 1. 16:9 固定舞台

内容区域固定 `1920×1080`，通过 `transform: scale()` 适配不同屏幕。**没有响应式布局**。

**为什么**：录屏输出是固定分辨率的视频（1080p / 4K），响应式布局在录屏场景下没有意义，反而增加不确定性。

**代码约束**：
```tsx
// Stage.tsx 固定尺寸
width: 1920
height: 1080
// useStageScale.ts 自动 scale
```

#### 2. 全局 step 计数器

章节是 step 的**纯函数**：`if (step === N) return <Scene />`。**没有定时器、没有 setTimeout、没有 requestAnimationFrame 驱动的自动推进**。

**为什么**：
- Auto 模式靠音频结束事件推进（`useAutoMode.ts`）
- Manual 模式靠用户点击/键盘推进
- 如果用定时器，音频和画面必然不同步

#### 3. 每步独占整屏

每个 step 返回一个**全屏场景**，没有侧边栏、没有底部信息栏、没有悬浮工具条。

**为什么**：
- 视频感需要**沉浸式体验**
- 任何持久性 UI 元素都会分散注意力（原则 #2）
- 进度条和翻页提示默认 `opacity: 0`，hover 时才显示

#### 4. 口播节拍 = Step

一节拍 = 一 step = 一聚焦想法。这是整个系统的**时间原子**。

**为什么**：
- 口播者念到哪，画面就该演到哪
- 如果一个 step 包含多个想法 → 观众眼睛不知道看哪（违反 #2）
- 如果一个想法跨多个 step → 节奏拖沓（违反 #1）

### P2 内容驱动层

#### 5. 隐藏的边角控件

进度条 / 翻页器 / 章节标题等控件默认**完全隐藏**（`opacity: 0`），只在鼠标悬停或触摸时淡入。

**为什么**：录制出来的视频不应该有任何 UI chrome —— 视众看到的是纯净的内容舞台。

#### 6. 舞台无 Chrome

**没有** header / footer / 页码 / 品牌 logo / 导航栏。

**为什么**：这不是 landing page，不是 admin panel，不是 dashboard。这是**视频叙事**。任何非内容的视觉元素都是噪音。

#### 7. 内容驱动动画（最重要的原则）

先找**内在动作**，找不到才用入场动画兜底。

**决策顺序**：

```
1. 这步内容本身有没有"动作"？
   → 数字变化？→ 用 Counter 动画
   → 对比关系？→ 用 Split / Mask 对比
   → 流程步骤？→ 用依次点亮
   → 因果关系？→ 用箭头/连线/遮挡揭示
   
2. 没有内在动作？
   → 用最轻量的 opacity 过渡（不是 fade，是瞬间出现）
   
3. 绝对禁止：
   → 全场同一种入场动画（slide / fade / blur 各章都一样）
   → 纯装饰性的持续微动（旋转的光圈、浮动的粒子背景）
     （除非该步内容本身就是关于"流动/变化"的）
```

**FAILURE 案例对照**：
- #8 同一种动画到底 → 违反本原则
- #20 动画超时 → 动画时长不匹配内容节奏
- #22 无意义 fade → 没有内在动作时用了装饰性动画

#### 8. 多点逐个揭示

清单 / 列表必须 **1 项 = 1 step**。**禁止同步 stagger 上 N 项**。

**正确做法**：
```
Step 3: [X] ✓ 亮起（Y/Z 灰化或隐藏）
Step 4: X 灰化 + [Y] ✓ 亮起
Step 5: X/Y 灰化 + [Z] ✓ 亮起
```

**错误做法**：
```
Step 3: [X] [Y] [Z] 同时 stagger 出现（❌ 认知过载）
```

**判断标准**：讲者会**一个一个**念出来吗？会 → 必须逐个揭示。

### P3 风格统一层

#### 9. 整片同一主题

**章节间不翻表面色**。颜色 / 字体走 theme token，其他尺度章节自由发挥。

**token 管什么**（必须统一）：
- 主色调 / 强调色 / 中性色层级
- 字体家族（标题 / 正文 / 等宽）
- hero 数字样式
- 卡片 / 分割线 / 装饰性格
- 圆角策略（全部圆角 / 全部直角 / 混合）

**章节自由管什么**：
- 具体动画类型和时长
- 信息密度和留白比例
- 视觉演示手法（数据图 vs 流程图 vs 对比图）
- 微交互细节

**为什么这样分层**：token 保证"看起来像一个作品"，自由保证"每章有自己的呼吸感"。

#### 10. 双源原则

**script.md 定节拍，article.md 定画面密度**。

- **节奏 / 顺序 / 切分** → 跟 script.md（关键顺序不能乱）
- **画面细节 / 数据 / 引用 / 案例** → 回 article.md 抽（通过 MATERIAL-INDEX.md 定位）

> 详见 [DESIGN-DECISIONS.md](DESIGN-DECISIONS.md) §双源原则
