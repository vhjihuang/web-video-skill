## 十条原则（索引）

| # | 原则 | 一句话 |
|---|------|--------|
| 1 | 16:9 固定舞台 | 内容 1920×1080 + transform scale |
| 2 | 全局 step 计数器 | 章节是 step 的纯函数，无定时器 |
| 3 | 每步独占整屏 | `if (step === N) return <FullScene />` |
| 4 | 口播节拍 = step | 一节拍 = 一 step = 一聚焦想法 |
| 5 | 隐藏的边角控件 | 进度条 / 翻页器默认 opacity 0 |
| 6 | 舞台无 chrome | 没有 header / footer / 页码 / 品牌条 |
| 7 | **内容驱动动画** | 先找内在动作，找不到才入场动画兜底 |
| 8 | 多点逐个揭示 | 1 项 = 1 step，禁同步 stagger 上 N 项 |
| 9 | 整片同一主题 | 颜色 / 字体走 token，其它尺度章节自由 |
| 10 | 双源原则 | script 定节拍，article 定画面密度 |

完整展开见 CHAPTER-CRAFT.md Part 0。

## 开工自检（5 问）

开工前问自己这 5 个问题，每个都要有明确答案再动代码：

1. **这一章的核心信息是什么？**（一个聚焦主题）
2. **口播在讲什么节奏？**（对应 narrations.ts 每条的语义）
3. **每步屏幕上观众眼睛该看哪里？**（焦点规划）
4. **用什么视觉演示？**（至少 1~2 处 CSS/SVG/Canvas/JS 动画）
5. **信息池里哪些数据挂到哪一步？**（双源落地）

## 内容驱动动画决策树

```
内容有内在动作？
├── 是 → 用内容驱动的演示（数字递增/排名交换/流程点亮/对比切开/形状变形）
│         → 这是最强的视频感来源
└── 否 → 有对比/递进/强调关系？
           ├── 是 → 用关系驱动的入场（聚光灯扫过/高亮切换/尺寸对比）
           └── 否 → 最后才用通用入场（fade in / blur clear / slide up）
                     → 全章都用同一种通用入场 = 验收不过
```

**持续微动慎用** —— 大多数场景不需要，用了反而抢戏。

## 视觉工具箱（按类型选）

| 类型 | 手段 | 适用场景 |
|------|------|---------|
| 数据变化 | CSS counter / JS requestAnimationFrame | 数字递增、排名交换、进度条生长 |

| 模拟交互 | DOM 模拟 | 终端、对话窗口、目录树、代码编辑器 |

## 时长参考

| 指标 | 值 | 说明 |
|------|-----|------|
| 口播语速 | ~4 字/秒（中文） | narration 字数 ÷ 4 ≈ 秒数 |
| Auto 模式缓冲 | 音频结束后 + 200ms | 然后 auto next() |
| 无音频退化 | `max(1500ms, 字数 × 250ms)` | narration 为空串或音频 404 时 |
| **动画时长上限** | **≤ 该步口播时长** | 超出会被 Auto 模式当场切断 |

## 反 AI 味反模式（视觉）

以下全部不要：

- 紫粉 / 蓝紫对角渐变背景
- 圆角卡片 + 彩色左边框装饰
- 渐变按钮 + 大圆角药丸
- **🔴 emoji 当独立图标用**（如 👨‍🏫 代表"老师"、📚 代表"书"）—— 跨平台渲染不一致，无法控制颜色/大小
- 🟡 emoji 作为**内容文字**的一部分（如 ❌→✅ 对比符号、⏭ 跳过标记）—— 允许但需在自检 C8 中标注
- ✅ 替代方案优先级：`<ImagePlaceholder>` > SVG path / CSS 几何图形 > Unicode 符号（如 ✓ ✗ → ← ↑）> emoji（最后手段）
- 假数据 / 假 logo / 假"X 万用户"
- 整章 N 步用同一种入场动画（全场 fade / 全场 blur）
- 每步都挂 ken burns / 光晕呼吸 / 持续闪烁
- 每屏右下角都挂 mono 角标 / 序号

缺的素材用 placeholder 占位卡（`"image · 16:9 描述"`）。**没有就承认没有，比 fake 强一百倍。**

## 创意激发：对抗"安全但平庸"陷阱

> **问题**：约束系统容易让 Agent 倾向于选择最安全的路径（如反复使用卡片列表+淡入动画），
> 导致整章视觉单调、缺乏记忆点。
> **本节是鼓励性指引（非强制），目标是每章至少有 1~2 处 Lv2+ 级别的视觉手法。**

### 视觉手法分级库

| 等级 | 手法 | 典型实现 | 适用场景 | 安全性 |
|------|------|---------|---------|--------|
| **Lv1 基础** | 卡片逐个 reveal | `opacity: 0→1` + `translateY: 20px→0` | 信息展示、列表呈现 | ★★★★★ 最安全 |
| | 色彩渐变 | `background: linear-gradient(...)` | 过渡页、背景氛围 | ★★★★★ |
| | 文字高亮 | 关键词 `color: var(--accent)` 弹入 | 口播强调点 | ★★★★☆ |
| **Lv2 进阶** ⬅️ **推荐每章 1~2 次** | 打字机效果 | CSS `@keyframes` + `width: 0→100%` 或 `ch` 单字显示 | 终端模拟、代码演示、Prompt 展示 | ★★★★☆ |
| | Counter 数字跳动 | JS `setInterval` 或 CSS `@property` 计数器 | 数据对比（"效率提升 10×"）| ★★★☆☆ |
| | 分屏切换 | `grid-template-columns: 1fr 1fr` + 左右交替 active | 新旧方案对比（❌→✅）| ★★★★☆ |
| | SVG 路径描边 | `stroke-dashoffset: pathLength → 0` | 进度展示、流程图绘制 | ★★★☆☆ |
| | 图片/色块 morph | CSS `clip-path: polygon()` 形变 | 状态转换（变化前→后）| ★★☆☆☆ |
| **Lv3 突破** 🔥 **仅第 1 章或章节高潮点** | DOM 终端完整模拟 | 完整窗口 + 标题栏 + 三色圆点 + 可交互元素 | 开场 Hook、核心概念演示 | ★★☆☆☆ 需要精确还原 |
| | 3D perspective | `perspective: 1000px` + `rotateX/Y` | 产品展示、空间关系表达 | ★★☆☆☆ |
| | 物理弹性效果 | `cubic-bezier(0.68, -0.55, 0.265, 1.55)` | 强调反馈、冲击力时刻 | ★☆☆☆☆ |
| | 动态数据可视化 | Canvas/SVG 实时绑定 | 大数据展示、趋势图 | ★☆☆☆☆ |

### 安全区自检

> 每章写完后，快速扫描一遍：

```
连续 3 个 step 的主导动作是否相同？
├── 是 → 你可能进入了安全区
│   └── 强制将其中 1 个 step 替换为 Lv2 或 Lv3 手法
│       参考上表选择与当前内容匹配的手法
└── 否 → ✅ 通过多样性检测

常见安全区信号：
  ⚠ 连续 3 步都是 "fade-in + 上移"
  ⚠ 连续 3 步都是 "卡片/列表 reveal"
  ⚠ 整章没有任何 "计数/打字/描边/分屏" 类动效
  ⚠ 所有 step 的视觉节奏完全一致（无快慢变化）
```

### 设计原则提醒

> **大胆 ≠ 复杂**。最好的视觉手法往往是：
> - 用简单的 CSS 属性创造意外效果（如 `outline-offset` + `animation` = 打字机）
> - 用数据本身讲故事（数字跳动比华丽动画更有说服力）
> - 用物理感建立真实感（弹性缓动比匀速移动更"有机"）
>
> **大胆 ≠ 违规**。Lv2/Lv3 手法仍需遵守：
> - 字号下限 / token 化 / 时长约束 / 物理隔离 —— 这些不因"创意"而豁免

## 代码硬规则（红线，触犯即不合格）

### token 使用（换主题不破的底线）

**必须走 token（禁硬编码）**：
- 颜色：`--shell` / `--surface` / `--surface-2` / `--surface-3` / `--text` / `--text-2` / `--text-mute` / `--text-faint` / `--rule` / `--accent` / `--accent-soft` / `--accent-glow`
- 字体家族：`--font-display-cn` / `--font-display-en` / `--font-body` / `--font-mono`
- 主题性格签名通过 primitive class 接入：`.hero-num` / `.rule` / `.card` / `.stage-frame`

**🔶 语义性硬编码例外（允许但必须标注）**：

以下场景允许使用具体颜色值，**前提是必须在 CSS 中用注释标注原因**：
> 格式：`/* SEMANTIC-HARDCODE: <原因> */`

| 场景 | 示例值 | 典型用途 | 推荐变量名 |
|------|--------|---------|-----------|
| 模拟 macOS Terminal 交通灯 | `#ff5f56` / `#ffbd2e` / `#27c93f` | 终端窗口装饰 | `var(--semantic-terminal-red)` 等 |
| 系统警告/错误色 | `#ff3b30` / `#dc3545` | 警告印章、错误状态 | `var(--semantic-warning)` |
| 品牌标准色 | 客户提供 | Logo、品牌标识 | `var(--semantic-brand)` |

> **白名单原则**：仅上述 3 类场景可例外。其他所有颜色（包括"我觉得这个蓝好看"）**仍必须走 token**。
> `base-typography.css` 已预定义 `--semantic-terminal-*` 和 `--semantic-warning` 变量，优先使用 var() 而非直接写 hex。

**可硬编码（章节自由）**：
- 字号 / 间距 / padding / margin
- 动画时长 / 缓动 / keyframe
- 边框宽度 / 一般圆角 / 字距
- gap / grid 布局尺寸

### 工程红线

- **不用 `setTimeout` / `setInterval` 驱动动画** —— 用 CSS keyframes
- 可交互元素加 `data-no-advance`，否则点击被舞台误推进
- 章节物理隔离：独立文件夹 / 独立 CSS 类前缀 / 不跨章 import / 不改共享文件

### narrations.ts（唯一真相源）

```typescript
// 必须与 <Chapter>.tsx 同目录
export const narrations: string[] = [
  // step 0 的口播文本（来自 script.md 对应段，语义一致）,
  // step 1 的口播文本,
  // ...
];
```

- 数组长度 **=** `if (step === N)` 最大 N + 1（不一致 = Auto 录屏错位）
- 每个元素 = 该 step 的口播文本（可为 TTS 微调标点，但不能漏关键短语）
- 完全无音频的过场 step 用空串 `""`
- 这是 **audio 合成 + Auto 推进的唯一真相源**

### 字号硬性下限（量化标准，v2 扩展版）

| 层级 | 元素类型 | 最小字号 | 典型使用场景 |
|------|---------|---------|-------------|
| **L1** | hero 标题 | **80px** | 全屏主标题，远观可读（如章节开场大字） |
| **L2** | 章节大标题 | **56px** | 章节内 group title / section header / prompt 内容主字 |
| **L3** | 副标题 / kicker | **48px** | 二级标题、过渡语 |
| **L4** | 正文 / 列表项 | **32px** | 主要阅读文字（卡片内容、列表项） |
| **L5** | 次要文字 | **24px** | badge 文字、辅助说明、metric label |
| **L6** | 标注 / cue / 元数据 | **18px** | 角标、来源标注、时间戳 |
| **L7** | 小标签 | **16px** | kicker、极短 tag（≤4 字）、terminal 提示符 |
| **L8** | 微型文字 | **14px** | 版权声明、页码、法律性文字 |

> **v2 变更说明**：从原 5 档扩展为 8 档，填补了 20~56px 区间的空白。
> 原 `body(28px)` 上调至 `32px` 以保证桌面端阅读舒适度；
> 原 `cue(18px)` 保持不变，新增 `label(16px)` 和 `micro(14px)` 细分极小区间。
> 对应 `base-typography.css` 新增 `.ty-sub-title` / `.ty-body-sm` / `.ty-label` class。

**低于上述值 = 不合格，回去改。**

## 完工自检清单（写完每章强制执行）

> **分层设计**：8 项**核心**（阻塞交付，必须全部通过）+ 10 项**建议**（不阻塞但需说明原因）。
>
> ### 🔧 可选辅助：自动化预检（~30秒）
>
> 以下两个命令可辅助自查，**不强制运行，结果仅供参考，不作为 pass/fail 判定依据**。
>
> **⚠️⚠️⚠️ 重要限制 ⚠️⚠️⚠️**
>
> 命令A 使用正则表达式匹配 TSX 源码，存在以下已知局限：
> - 无法识别 `switch(step)` / `step >= N && step <= M` 等非字面量写法
> - 注释中的 `if (step === X)` 可能被误匹配
> - 只统计 `if (step === N)` 的最大 N，无法覆盖动态计算场景
>
> **命令显示 PASS ≠ 真的没问题**（可能漏检），**命令显示 FAIL 大概率有问题但也不排除误报**。
> 此工具的价值在于**提醒你关注 C1 和 IM 粒度**，而非**替代你人工检查 C1 和 IM 粒度**。
> 最终判定以人工确认为准。
>
> ---
>
> **命令A - C1 narrations一致性快速提示**：
> ```bash
> cd presentation/src/chapters/<本章目录> && \
> TSX_STEPS=$(grep -oE 'if \(step === [0-9]+\)|case [0-9]+:' *.tsx | grep -oE '[0-9]+' | sort -n | tail -1) && \
> NARR_COUNT=$(grep -cE '^\s*"[^"]*",?\s*$' narrations.ts || echo 0) && \
> echo "tsx maxStep=$TSX_STEPS → expected narrations=$((TSX_STEPS + 1)), actual=$NARR_COUNT" && \
> [[ $((TSX_STEPS + 1)) -eq "$NARR_COUNT" ]] && echo "✅ C1 PASS" || echo "❌ C1 FAIL"
> ```
>
> **命令B - IM粒度批量扫描**：
> ```bash
> cd presentation && bash scripts/validate-im.sh --chapter <本章id>
> ```
>
> 如在汇报中粘贴了输出，放在「可选辅助输出」区域即可。不粘贴不影响验收。
>
> ---
>
> 执行方式：优先 Agent Teams reviewer → 其次 subAgent → 兜底自己逐项核查。
> **拿到结论后先按 fail 项改完代码，再汇报本章交付。直接拿原始结论汇报但不修复 = 违规。**

## 常见反馈速查

| 用户说 | 可能原因 | 改法 |
|--------|---------|------|
| "字体太小" | 字号低于下限标准 | 按「字号硬性下限」表调大 |
| "太空 / 内容太少" | 没回 article 抽细节 | 挂信息池数据到具体 step |
| "像 PPT" | 纯文字 / 同一动画 / 无视觉演示 | 加 CSS/SVG 演示 + 变化动画 |
| "太花哨" | 每步都有持续微动 / ken burns | 砍掉装饰动画，保留内容驱动 |
| "看不懂在讲什么" | 信息太密或缺少焦点 | 每步只放 1~3 个东西，hero 明确 |
| "节奏太快 / 太慢" | step 切分不合理 | 拆 step 或合并 step（同步改 narrations.ts） |
| "风格不统一" | 硬编码了颜色/字体 | 改为消费 token |

**定位层级再改最小切片，不要重做整章。**

## 增量修改硬规则（IM，编辑代码时必须遵守）

> **根因**：全量重写文件会导致 Token 浪费（95% 重复输出）、上下文丢失（无意改动扩散）、
> 并行冲突（最后写入者胜）。以下规则确保每次修改**精准命中目标**。
>
> **⚠️ 三个安全阀（满足任一条件可回退为全量替换，但必须说明原因）**：
>
> 1. **联动阈值**：单次修改涉及 **≥ 4 处**跨区域联动（如新增 step 需同时改 tsx + css + narrations + chapters.ts）
> 2. **重构场景**：修改涉及代码结构变化（如布局从上下改为左右、组件拆分合并）
> 3. **阶段豁免**：Phase 2.2（第 1 章首次生成）允许全量输出；IM 规则主要适用于 Phase 2.3（迭代修复）

### IM-0：适用范围判定

```
修改前先判断：
├── 是首次生成整章？          → 全量输出（Phase 2.2 豁免）
├── 是单值/单行修复？        → IM-1~IM-5 增量修改 ✅
├── 涉及 2~3 处联动变更？     → 允许批量 IM（一次 SearchReplace 含多处）
└── 涉及结构性重构或 ≥4 处？ → 允许全量（需在输出中标注原因）
```

### IM-1：精确边界（不包含无关代码区域）

**核心原则**：`old_str` 的范围应**恰好覆盖你需要修改的代码块**，不多不少。
**禁止的是"用整个文件做 old_str"**，而不是"限制绝对行数"。

**按修改粒度分级**（实际 step 分支平均 30~50 行）：

| 粒度 | 典型场景 | 允许的 old_str 范围 | 示例 |
|------|---------|-------------------|------|
| **L1 属性级** | 改字号/颜色/间距/文本 | **1~5 行**（单个 CSS 声明或 JSX 属性） | `.badge { font-size: 20px }` → `32px` |
| **L2 元素级** | 改一个 div / 组件 / 标签块 | **5~20 行**（单个 JSX 元素或 CSS class 块） | 替换一张卡片的完整结构 |
| **L3 分支级** | 重构一个 step 的布局 | **整个 step 分支**（20~60 行） | 将 step 2 从竖排改为横排 |
| **L4 文件级** | ❌ **禁止**（除非触发安全阀 #1~#3） | 整个 .tsx / .css 文件 | — |

```
✅ 正确（L1）：old_str = ".cd-badge { font-size: 20px; }" （1行）
✅ 正确（L2）：old_str = 整个 <div className="cd-card">...</div> 块（12行）
✅ 正确（L3）：old_str = if (step === 2) { return (...); } 整个分支（45行）
❌ 错误（L4）：old_str = 整个 switch 语句 + 所有分支（200行）
❌ 错误（越界）：old_str 包含了 step 3 的代码但你只想改 step 2
```

### IM-2：追加/插入语义优先

**规则**：新增内容时，选择"在指定位置追加"而非"替换包含后续内容的块"。
**适用场景**：新增 step 分支、新增 CSS class、narrations 追加条目。

```
✅ 正确：old_str = "case 2: return (...);" → new_str = "case 2: ...\ncase 3: return (...);"
❌ 错误：old_str = case 2 + case 3 的所有代码 → new_str = 全部重新输出
```

### IM-3：共享文件用 patch 指令

**规则**：修改 `chapters.ts`、`App.tsx` 等共享文件时，输出明确的 **patch 描述**而非完整重写。
**格式**：

```
在 chapters.ts 数组的 [位置] 追加：
{ id: '04-methods', title: '快速跨域的 AI 三板斧', component: Methods }
```

### IM-4：数组文件只做原子操作

**规则**：`narrations.ts` 等数组类文件，**禁止整体重赋值**。
允许的操作：
- `push()` — 在末尾追加新 step
- `splice(index, 0, item)` — 在指定位置插入
- `splice(index, 1)` — 删除指定项
- `array[index] = newValue` — 替换指定项

```
✅ 正确："在 narrations 数组 index 4 处 splice 插入 '新增内容'"
❌ 错误：输出整个新的 narrations 数组（20+ 行）
```

### IM-5：CSS 修改限定目标选择器

**规则**：调整样式时，old_str/new_str 仅包含**目标 class 的定义块**，
不涉及同文件中其他无关 class。

```
✅ 正确：old_str = ".cd-intro-badge { font-size: 20px; }"
         new_str = ".cd-intro-badge { font-size: 24px; }"
❌ 错误：old_str = 整个 .css 文件中所有 class 定义
```

## 反模式速查（违反 IM 规则的典型表现）

| 表现 | 违反的 IM | 后果 |
|------|---------|------|
| 每次"修复字体大小"都重写整个 .css 文件 | IM-1 / IM-5 | diff 噪音大、无意改动其他 class |
| 新增 step 时重写整个 switch/case 块 | IM-1 / IM-2 | 可能丢失其他 step 的正确逻辑 |
| 多个 subagent 各自输出完整 chapters.ts | IM-3 | 并行合并冲突 |
| narrations.ts 每次同步都输出完整数组 | IM-4 | 排序错位风险 |
| 修改一个颜色值却替换了整行周围代码 | IM-1 | 引入格式化差异（空格/缩进变化） |
